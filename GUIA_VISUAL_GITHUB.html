Guía visual: publicar el Dashboard de RRHH en GitHub

Del Paso 3 al final, con maqueta de cada pantalla y el botón exacto señalado. Los enlaces de esta guía te llevan directo: no tienes que buscar nada en el menú.

Escríbelo y todos los enlaces de la guía quedan listos para hacer clic.
Dos cosas que hacen fallar los enlaces.
1. El usuario que se pide arriba es tu nombre de usuario, el que aparece en la URL de tu perfil (github.com/ese-de-aqui), no tu nombre para mostrar. Si tu perfil dice "Daniel López" pero tu usuario es dlopez-mrt, va el segundo.
2. Esta guía asume que el repositorio se llama dashboard-rrhh, como en el Paso 2. Si le pusiste otro nombre, sustitúyelo en los enlaces.

Abre solo el repositorio, sin nada más
https://github.com/TU-USUARIO/dashboard-rrhh

También da 404 El problema es la dirección, no el paso. Revisa, en este orden:
  • Tu nombre de usuario. Ábrelo desde tu propia foto de perfil (arriba a la derecha) → Your profile, y copia el usuario de la barra de direcciones. Ese es el que va arriba en esta guía.
  • El nombre del repositorio. Foto de perfil → Your repositories. Ahí ves el nombre exacto, con sus guiones y mayúsculas. GitHub distingue entre dashboard-rrhh y Dashboard-RRHH.
  • Que estés con la sesión iniciada y en la cuenta correcta. Un repositorio privado al que no tienes acceso también responde 404, no "prohibido".
Sí abre el repositorio Entonces falta la rama main: un repositorio sin ningún archivo todavía no tiene ramas, y por eso cualquier enlace que termine en /main da 404. Significa que el Paso 3 no se completó. Vuelve al Paso 3, sube los archivos y confirma que la página del repositorio muestre las carpetas data, etl, public. Con eso, los enlaces del Paso 4 en adelante funcionan.
Abre y ya tiene archivos Revisa cómo se llama tu rama principal: en la pestaña Code, el botón del lado izquierdo arriba de la lista de archivos dice el nombre. Casi siempre es main; si dijera master, cambia /main por /master en los enlaces de esta guía.

La ruta que nunca falla

Los enlaces directos son un atajo, no la única vía. Desde la página del repositorio, el botón Add file ▾ te lleva a lo mismo sin depender de la rama ni de la URL. La maqueta del Paso 4 te muestra dónde está.

3 Subir los archivos ≈ 4 min

Ir directo a esta pantalla
https://github.com/TU-USUARIO/dashboard-rrhh/upload/main

Si el repositorio está recién creado y todavía vacío, esta URL puede no abrir. En ese caso usa el enlace que aparece en la pantalla de bienvenida del repositorio, señalado abajo con ①.

Al crear el repositorio caes en una pantalla de bienvenida titulada Quick setup. Se ve así:

  1. Clic en uploading an existing file ①. Es texto azul dentro de la frase "Get started by creating a new file or uploading an existing file".
  2. Se abre la pantalla de carga, con un recuadro punteado grande en el centro.
  3. Vas a arrastrar 9 cosas, no 43 archivos. Entra a la carpeta repositorio-para-github y selecciona con Ctrl+A (Windows) o Cmd+A (Mac) exactamente estos 9 elementos:
    5 carpetas — sin abrirlas4 archivos
    data · etl · plantillas · public · tests README.md · package.json
    INSTALACION_GITHUB.md · GUIA_VISUAL_GITHUB.html
  4. No entres a las carpetas. Se arrastran cerradas: GitHub las abre solo y conserva la estructura. Si entras a etl y seleccionas los archivos de adentro, llegan sueltos a la raíz y nada funciona.
  5. Arrastra los 9 elementos al recuadro punteado ②.
    Tiene que ser arrastrando. El botón choose your files abre el explorador de archivos de Windows, y ese no puede cargar carpetas: aplana todo.
  6. Espera. GitHub tarda unos segundos en recorrer las subcarpetas. Al terminar reporta 43 archivos — ese es el número que GitHub cuenta después de abrir las carpetas, no el número de cosas que seleccionaste.
  7. En el campo de mensaje ③ escribe Carga inicial del Dashboard de RRHH.
  8. Botón verde Commit changes ④.

Si no lo encuentras

  • No veo "uploading an existing file". Es porque el repositorio ya tiene archivos y esa pantalla de bienvenida desapareció. Usa el enlace directo de arriba, o: pestaña Code → botón Add file ▾ (arriba a la derecha, junto al botón verde Code) → Upload files.
  • Solo subió 5 o 6 archivos. Soltaste antes de que el navegador terminara de leer las subcarpetas. Vuelve a arrastrar y espera a que la lista deje de crecer.
  • Aparece una carpeta dashboard-rrhh dentro del repositorio. Arrastraste la carpeta en vez de su contenido. Bórrala y repite: en el repositorio, clic en la carpeta → botón ⋯ → Delete directory.
  • Dice que el archivo es muy grande. No debería pasar: el más grande es BASE_RRHH.xlsx con unos 180 KB, y el límite de GitHub por archivo es 25 MB en la carga web.

Verifica la estructura antes de seguir

Diez segundos aquí evitan rehacer todo el trabajo. En la página del repositorio:

  • Arriba de la lista deben aparecer 5 renglones con icono de carpeta: data, etl, plantillas, public, tests. Las carpetas van primero, antes de los archivos.
  • Haz clic en public. Adentro debe estar index.html y una carpeta assets.
  • Abajo se ve el README.md renderizado, con el título Dashboard de RRHH — Minera Rio Tinto.

Señal de alarma: la estructura se aplanó

Si en la raíz ves index.html, app.js, styles.css, build.py o BASE_RRHH.xlsx sueltos, sin carpetas, la carga perdió la estructura. No sigas al Paso 4: sobre una estructura aplanada, nada del resto funciona. El tablero busca public/index.html y el ETL busca data/BASE_RRHH.xlsx; si están en la raíz, no los encuentra.

La carga web de GitHub no tiene borrado masivo, y quitar 43 archivos uno por uno es peor que empezar de nuevo. Como son datos demo y no hay nada que perder, lo más rápido es borrar el repositorio y volver a crearlo:

  1. Settings → General, hasta abajo, zona roja Danger Zone → Delete this repository. GitHub pide escribir el nombre completo para confirmar.
  2. Vuelve a crearlo igual que en el Paso 2, con el mismo nombre.
  3. Repite este Paso 3 arrastrando las 5 carpetas cerradas, no su contenido.
  4. Verifica la estructura con la lista de arriba antes de pasar al Paso 4.

Si prefieres no borrar el repositorio: con el repositorio abierto presiona la tecla . (punto). Se abre un editor tipo VS Code dentro del navegador, donde sí puedes seleccionar varios archivos y borrarlos de una vez, y arrastrar carpetas completas.

4 Crear el archivo de automatización ≈ 3 min

Por qué este paso es aparte. El archivo debe quedar en una carpeta llamada .github. Las carpetas que empiezan con punto están ocultas en Windows y Mac, y el navegador no las sube al arrastrar. Por eso se crea escribiendo la ruta a mano: GitHub crea las carpetas solo.

Empieza por aquí: la ruta por menú. Es la que funciona siempre, sin depender de la URL ni del nombre de la rama. Desde la página principal de tu repositorio:

Atajo, si prefieres pegar la URL
https://github.com/TU-USUARIO/dashboard-rrhh/new/main

Este atajo da 404 si el repositorio todavía no tiene archivos, porque en ese estado no existe la rama main. Si te pasó eso, ve al bloque ¿Un enlace te dio 404? del inicio de esta guía: la causa está ahí.

  1. Add file ▾ → Create new file. (O el atajo de arriba.)
  2. Ya en el editor (segunda maqueta, abajo), en el campo del nombre ① escribe, letra por letra:
    .github/workflows/deploy.yml
    No copies y pegues si puedes evitarlo: al teclear cada / verás cómo GitHub va creando la carpeta y moviendo el cursor. Así confirmas que quedó bien.
  3. Abre el archivo deploy.yml del paquete con el Bloc de notas (Windows) o TextEdit (Mac). No lo abras con Excel ni con Word.
  4. Selecciona todo (Ctrl+A / Cmd+A), copia, y pega en el editor grande ②.
  5. No toques la indentación. YAML usa los espacios del inicio de cada línea para entender la estructura: si "acomodas" el texto, deja de funcionar.
  6. Botón Commit changes… ③. Se abre una ventanita: escribe Agrega automatización de publicación y confirma con Commit changes.

Si no lo encuentras

  • El atajo de la URL me da 404. Lo más probable es que el repositorio todavía esté vacío: sin archivos no existe la rama main, y el enlace no resuelve. Revisa el bloque ¿Un enlace te dio 404? del inicio; ahí está la prueba de un paso para saber cuál de las causas es.
  • No veo el botón "Add file". Está en la pestaña Code, en la misma barra del selector de rama, a la izquierda del botón verde Code. En pantallas angostas se convierte en un +.
  • Escribí la ruta pero no se crearon las carpetas. Revisa que el punto inicial esté ahí: es .github, no github. Si quedó mal, borra el archivo y repite.
  • Después de guardar no veo la carpeta .github. Sí está — GitHub la lista al inicio, arriba de data. Si no aparece, recarga la página.

Cómo saber que quedó

En la raíz del repositorio aparece la carpeta .github. Y en la pestaña Actions aparece una corrida nueva llamada Agrega automatización de publicación: puede estar en amarillo (corriendo) o en rojo (falló al publicar). Las dos cosas son normales en este punto, porque Pages todavía no está activado. Eso es el Paso 5.

5 Activar GitHub Pages ≈ 1 min

Ir directo a esta pantalla
https://github.com/TU-USUARIO/dashboard-rrhh/settings/pages

Este es el paso que más se pierde en el menú, porque Pages está en la barra lateral de Settings, bastante abajo.

  1. Pestaña ⚙ Settings ①. Está en la fila de pestañas del repositorio, al final, después de Insights. No la confundas con la configuración de tu cuenta, que está en el menú de tu foto de perfil, arriba a la derecha.
  2. En la barra lateral izquierda, baja hasta el bloque Code and automation y haz clic en Pages ②.
  3. En Build and deployment → Source ③, abre el desplegable y elige GitHub Actions. Por defecto viene en Deploy from a branch.

Si no lo encuentras

  • No veo la pestaña Settings. Solo aparece si eres dueño o administrador del repositorio. Si lo creaste tú, ahí está — puede estar escondida detrás de un ⋯ en pantallas angostas.
  • No veo "Pages" en la barra lateral. Hay que bajar: la lista es larga. Está entre Webhooks y Environments. Usa el enlace directo de arriba.
  • Dice que Pages no está disponible. Pasa si el repositorio es privado en plan gratuito. Ponlo en público: Settings → General → Danger Zone → Change repository visibility.
  • No encuentro dónde guardar. No hay botón. El cambio se aplica al seleccionar la opción del desplegable.

Cómo saber que quedó

La misma pantalla muestra el desplegable en GitHub Actions y, tras la primera publicación, una franja arriba con "Your site is live at https://…" y un botón Visit site.

  5. Recarga la página. Aparece una corrida nueva en amarillo. Haz clic para ver el avance.

  • No veo el botón "Run workflow". Estás en la lista general de corridas. Tienes que entrar primero al workflow por su nombre, en la barra lateral izquierda ②.

  • Falló y no sé por qué. Clic en la corrida roja → clic en el trabajo verificar → busca el paso con la ✕ roja y ábrelo. El error de datos te dice hoja y fila, por ejemplo [hoja fact_ausentismo fila 148] regla violada: …

Tu tablero publicado
https://TU-USUARIO.github.io/dashboard-rrhh/

Ojo: es github.io, no github.com. Guarda este enlace en favoritos, es la dirección definitiva del tablero.

También la encuentras en tres lugares del repositorio:

  • Actions → la corrida → trabajo publicar → el resumen muestra la URL.
  • Settings → Pages → franja de arriba, botón Visit site.
  • Pestaña Code → panel derecho, sección Deployments → github-pages.

Si te da 404

  • Espera un minuto y recarga. La primera publicación tarda en propagarse.
  • Revisa que el trabajo publicar haya terminado en verde.
  • Verifica la diagonal final: /dashboard-rrhh/ con diagonal al cierre.
  • Confirma que el nombre del repositorio en la URL sea exactamente el que creaste, respetando mayúsculas y guiones.

8 Verificar que quedó bien ≈ 2 min

Recorre esta lista en el tablero abierto. Si algo falla, la última sección de esta guía tiene el diagnóstico.

  • El encabezado dice Cierre julio 2026 y muestra un commit de 7 caracteres.
  • Aparece la franja naranja de Datos de demostración.
  • Las tarjetas muestran números, no guiones.
  • Las cinco pestañas abren sin error: Resumen ejecutivo · Plantilla, rotación y ausentismo · Nómina y costo laboral · Capacitación y relaciones laborales · Base de datos.
  • En Resumen ejecutivo, la matriz tiene encabezado negro y las filas en verde, naranja y gris.
  • En Base de datos, la trazabilidad dice fuente: data/BASE_RRHH.xlsx (libro de Excel).
  • Al pasar el cursor sobre una gráfica sale el globo con los valores.
  • Al hacer clic en un chip de unidad, los números cambian.
  • El botón Ver tabla de cualquier gráfica muestra los datos en tabla.

↻ Rutina mensual: subir el cierre ≈ 5 min + captura

El trabajo del mes se hace en Excel. GitHub solo recibe el archivo.

a) Bajar el libro

Descarga directa del libro
https://github.com/TU-USUARIO/dashboard-rrhh/raw/main/data/BASE_RRHH.xlsx

Baja el libro del repositorio cada mes antes de capturar, en lugar de trabajar sobre una copia vieja de tu computadora. Así partes de lo último publicado y no pisas lo que haya cargado alguien más del equipo.

b) Capturar en Excel

Abre el libro y, en cada hoja fact_*, agrega las filas del mes nuevo con su periodo — por ejemplo 2026-08.

  • Agregar filas, no sobrescribir. El tablero calcula rotación y las demás tasas anualizadas con ventana móvil de 12 meses: si borras historia, esos indicadores dejan de poder calcularse.
  • Usa los desplegables de unidad_id, area_id, tipo_relacion y turno en lugar de escribir a mano.
  • Revisa la hoja LEEME: el bloque Registros cargados te dice cuántas filas quedaron en cada hoja.
  • Guarda como .xlsx y con el mismo nombre: BASE_RRHH.xlsx.

c) Subir el libro

Ir directo a la carga
https://github.com/TU-USUARIO/dashboard-rrhh/upload/main/data

Este enlace abre la carga ya dentro de la carpeta data, que es donde debe caer el libro. Si subes el archivo en la raíz del repositorio, el tablero no lo encuentra.

  1. Arrastra tu BASE_RRHH.xlsx al recuadro punteado. GitHub reemplaza el anterior porque tiene el mismo nombre.
  2. Verifica que arriba diga la ruta dashboard-rrhh / data /.
  3. Mensaje del commit: Cierre 2026-08.
  4. Commit changes. Actions valida y republica solo en un par de minutos.

d) Revisar qué cambió

Historial legible del cierre
https://github.com/TU-USUARIO/dashboard-rrhh/commits/main/data/csv

Un .xlsx es binario: GitHub puede guardarlo, pero no mostrarte qué cambió adentro. Por eso el proceso exporta los datos a data/csv/ en cada corrida. Ahí puedes ver, línea por línea, qué número cambió en cada cierre y quién lo cambió. No edites esos CSV: se regeneran solos.

Recuerda

Si la validación falla, el tablero no se actualiza y conserva el cierre anterior. Es a propósito: es mejor llegar al comité con el dato del mes pasado que con un dato equivocado. Corriges la celda, vuelves a subir el libro, y listo.

Repositorio público. Mientras el repositorio sea público, carga únicamente el libro con los datos demo. GitHub Pages en repositorio privado requiere plan GitHub Team o superior; el README.md del repositorio tiene la sección Seguridad de los datos con la ruta de migración.
